### 1.2 核心模块架构

#### 1.2.1 用户管理模块
- **功能**: 用户注册、登录、信息管理
- **主要组件**: 
  - `user_router.py`: 用户相关API端点
  - `user_service.py`: 用户业务逻辑
  - User数据模型: 存储用户基本信息

#### 1.2.2 面试题库管理模块
- **功能**: 按岗位和难度管理和查询面试题目
- **题库覆盖范围**:
  - BigData (大数据开发工程师)
  - IoT (物联网解决方案架构师)
  - AI (机器学习工程师)
- **难度等级**: 简单、中等、困难

#### 1.2.3 模拟面试模块 (核心模块)
- **功能**: 实时面试交互、视频处理、语音识别、问题生成、评分报告
- **技术特点**:
  - WebSocket实时双向通信
  - 异步处理，支持多用户并发
  - 视频片段分割和缓存
  - 后台线程池处理耗时任务
- **主要流程**:
  1. 建立WebSocket连接
  2. 发送第一个开场问题
  3. 接收和处理用户回答视频
  4. 生成后续问题
  5. 超时检测和自动结束
  6. 后台生成综合评测报告

#### 1.2.4 分析与评测模块
- **功能**: 多维度面试表现分析
- **分析维度**:
  - 身体姿态分析 (Pose Analysis)
  - 情绪识别 (Emotion Detection)
  - 眼神接触 (Eye Contact)
  - 手部移动 (Hand Movement)
  - 身体整体移动 (Object Tracking)
  - 言语流畅度、语速、语调 (Speech Analysis)
  - 个性化学习推荐
- **输出**: 综合评分和改进建议

#### 1.2.5 AI助手模块
- **功能**: 提供面试相关问题的AI回答
- **技术**: 集成讯飞Spark大模型
- **特点**: 支持多轮对话

#### 1.2.6 文件管理模块
- **功能**: 头像、简历、视频、报告的上传和下载
- **存储结构**:
  - `/DataFile/Resume/` - 用户简历
  - `/DataFile/Avatar/` - 用户头像
  - `/DataFile/Video/` - 面试视频
  - `/DataFile/Reports/` - 面试报告
- **支持格式**:
  - 头像: JPG, PNG, GIF, WebP
  - 简历: PDF
  - 视频: WebM (面试过程中), MP4等 (下载时)

### 2.4 面试与评测接口

#### 2.4.1 WebSocket 实时面试连接

| 属性 | 值 |
|------|-----|
| **端点** | `/interview/ws` |
| **协议** | WebSocket |
| **认证** | 否 (Query参数验证) |
| **描述** | 建立实时面试WebSocket连接 |

**连接参数** (Query String):
```
ws://host:port/interview/ws?id=user123&date=2025-07-09%2000:00:00&resume=/path/to/resume.pdf&selected_job=bigdata
```

| 参数 | 类型 | 必需 | 说明 |
|------|------|-----|------|
| `id` | string | ✓ | 用户账号ID |
| `date` | string | ✓ | 面试日期时间 (格式: YYYY-MM-DD HH:MM:SS) |
| `resume` | string | ✓ | 简历文件路径 |
| `selected_job` | string | ✓ | 面试岗位 (bigdata/internetofthings/ai) |

**WebSocket 消息格式**:

接收消息 (二进制):
```
WebM格式的视频流数据 (VP8/VP9 + Vorbis/Opus)
12秒为一个完整片段
```

发送消息 (文本):
```
"请简单做一下自我介绍"
"根据您的简历，请介绍一下XXX项目的技术架构"
"面试结束，感谢您的参与！您的评测报告已生成，reportID: 12345"
```

**连接流程**:
1. 建立连接后，立即接收第一个问题
2. 持续发送视频流数据 (WebM格式)
3. 12秒无数据时，自动超时结束该片段
4. 接收下一个问题或面试结束信号
5. 循环直到面试结束

**可能的错误**:
- `400`: 缺少必需参数
- `500`: 服务器内部错误

### 2.8 认证与授权

**认证方案**: JWT (JSON Web Token)

**Token获取**:
- 通过 `/api/users/login` 登录成功后获得

**Token使用**:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Token结构**:
```
Header: {
  "alg": "HS256",
  "typ": "JWT"
}

Payload: {
  "sub": "user123",          // subject (accountID)
  "exp": 1234567890,         // expiration time (24小时后)
  "iat": 1234567800,         // issued at
  "role": "user"             // user role
}
```

**需要认证的资源**:
- `/api/users/{accountID}` - GET/PUT
- `/api/interview/*` - 所有操作
- `/api/ai/ask` - POST
- `/api/download/*` - 所有操作

**无需认证的资源**:
- `/api/users/register` - POST
- `/api/users/login` - POST

### 4.3 异常处理流程

| 异常类型 | 触发条件 | 处理方案 |
|---------|--------|--------|
| 数据库连接失败 | 数据库离线 | 返回500错误，记录日志 |
| 文件上传超大 | 文件>限制大小 | 返回413错误，提示用户 |
| 文件格式错误 | 非允许格式 | 返回400错误，拒绝上传 |
| WebSocket连接中断 | 网络问题 | 停止录制，后台清理资源 |
| 视频处理失败 | FFmpeg处理出错 | 记录日志，标记为失败 |
| ASR识别失败 | 语音模块错误 | 使用默认问题/重试 |
| LLM服务不可用 | AI服务离线 | 使用本地题库备选方案 |
| 报告生成超时 | 后台处理超时 | 异步继续处理，通知用户 |

### 5.4 认证与授权

#### 5.4.1 认证方案

- **方案**: JWT (JSON Web Token)
- **签发**: 用户登录成功后签发
- **有效期**: 24小时 (可配置)
- **刷新机制**: 支持Token刷新端点

**JWT Token结构**:
```
Header: {
  "alg": "HS256",
  "typ": "JWT"
}

Payload: {
  "sub": "user123",        // subject (accountID)
  "exp": 1234567890,       // expiration time
  "iat": 1234567800,       // issued at
  "role": "user"           // user role
}

Signature: HMACSHA256(base64(header) + "." + base64(payload), secret)
```
