## 1. 项目概述

### 1.1 项目背景

#### 1.1.1 行业痛点
当前求职者在面试准备过程中面临以下核心痛点:
- **缺乏真实环境模拟**: 传统面试练习无法还原真实面试场景的紧张感和互动性
- **难以自我察觉问题**: 求职者无法客观观察自己的肢体语言、表情管理和情绪状态
- **缺少个性化反馈**: 传统模拟面试难以提供细致入微的量化评估和针对性建议
- **反馈主观性强**: 人工评估受评委经验影响大，标准不统一
- **成本高昂**: 专业面试辅导价格昂贵，难以普及

#### 1.1.2 市场机会
- **求职群体庞大**: 每年高校毕业生超 1000 万，加上职场跳槽人员，市场规模巨大
- **AI 技术成熟**: 多模态 AI 技术 (语音识别、计算机视觉、大语言模型) 已具备商业化应用能力
- **在线教育发展**: 疫情加速了在线教育和远程面试的普及，用户接受度提高
- **政策支持**: 国家鼓励"互联网 + 教育"和人工智能产业发展

### 1.2 产品定位

**产品名称**: 模拟面试智能体系统 (Mock Interview Agent System)

**产品类型**: 基于多模态 AI 技术的智能化模拟面试平台

**核心价值主张**:
- 提供沉浸式实时音视频交互面试体验
- 通过 AI 技术进行全方位量化评估
- 生成个性化改进建议和训练路线

**目标用户群体**:
| 用户类别 | 占比 | 核心需求 | 使用场景 |
|---------|------|---------|---------|
| 应届毕业生 | 60% | 面试经验积累、能力提升 | 校招前集中练习 |
| 职场人士 | 25% | 技能提升、跳槽准备 | 业余时间自我提升 |
| 技术人员 | 10% | 技术面试专项训练 | 跳槽前针对性练习 |
| 其他人群 | 5% | 通用面试能力提升 | 各类面试场景 |

### 2.2 用户管理模块 (UM)

#### 2.2.1 UM-001: 用户注册

**需求描述**: 系统应允许新用户注册账户，支持可选的头像和简历上传

**功能详细说明**:

| 属性项 | 详细说明 |
|--------|----------|
| **标识符** | UM-001 |
| **名称** | 用户注册 |
| **优先级** | P0 - 最高优先级 |
| **业务价值** | 用户准入的第一道门槛，影响转化率 |
| **使用频率** | 一次性操作，但高频尝试 (考虑注册失败重试) |

**输入数据**:

| 字段名 | 类型 | 必填 | 约束 | 说明 |
|--------|------|------|------|------|
| accountID | String(25) | ✓ | 唯一，字母数字组合 | 用户账号 ID |
| password | String | ✓ | 最小 6 位 | 登录密码 |
| nickName | String(50) | ✓ | - | 用户昵称 |
| schoolName | String(50) | ✓ | - | 学校名称 |
| major | String(50) | ✓ | - | 专业名称 |
| qualification | Enum | ✓ | ['高职','本科','研究生','博士'] | 学历 |
| grade | String(15) | ✓ | - | 年级 (如：本科二年级) |
| birthday | DateTime | ✗ | - | 生日 |
| avatar | File | ✗ | JPG/PNG/GIF/WebP, ≤5MB | 头像文件 |
| resume | File | ✗ | PDF, ≤10MB | 简历文件 |

**处理逻辑**:

```
1. 验证账号唯一性
   ├─ 查询 database 中是否存在相同 accountID
   └─ 如存在，返回错误"账户已存在"

2. 密码加密处理
   ├─ 使用 bcrypt 算法进行哈希
   └─ salt rounds = 10

3. 头像文件处理 (如果提供)
   ├─ 验证 MIME 类型 (image/jpeg, image/png, image/gif, image/webp)
   ├─ 验证文件大小 (≤5MB)
   ├─ 生成文件名：{accountID}.{ext}
   ├─ 保存到 DataFile/Avatar/目录
   └─ 设置 user.avatar = True

4. 简历文件处理 (如果提供)
   ├─ 验证 MIME 类型 (application/pdf)
   ├─ 验证文件大小 (≤10MB)
   ├─ 生成文件名：{accountID}.pdf
   ├─ 保存到 DataFile/Resume/目录
   └─ 设置 user.resume = True

5. 创建用户记录
   ├─ 构建 User 对象
   ├─ 设置 createTime = 当前时间
   ├─ 插入数据库
   └─ 提交事务

6. 返回成功响应
```

**输出数据**:

**成功响应** (HTTP 201):
```json
{
  "code": 201,
  "message": "用户注册成功",
  "data": {
    "accountID": "user123",
    "nickName": "张三"
  }
}
```

**失败响应**:
- 账户已存在 (HTTP 400): `{"code": 400, "message": "注册信息无效或账户已存在"}`
- 头像格式错误 (HTTP 400): `{"code": 400, "message": "头像只允许上传 JPG, PNG, GIF, WebP 格式的图片"}`
- 简历格式错误 (HTTP 400): `{"code": 400, "message": "简历只允许上传 PDF 格式的文件"}`
- 服务器错误 (HTTP 500): `{"code": 500, "message": "用户注册失败，请稍后再试"}`

**异常处理**:
- 数据库异常：回滚事务，返回 500 错误
- 文件保存失败：回滚数据库操作，删除已保存文件，返回 500 错误
- 验证失败：立即返回 400 错误，不回滚

**验收标准**:
- [ ] 正确账号可以成功注册
- [ ] 重复账号注册被拒绝
- [ ] 密码加密存储 (数据库中不可见明文)
- [ ] 头像文件格式验证有效
- [ ] 简历文件格式验证有效
- [ ] 注册后 avatar/resume 字段正确设置
- [ ] 异常情况下数据一致性保持

**接口定义**:
- **端点**: `POST /api/users/register`
- **Content-Type**: `multipart/form-data`
- **认证**: 不需要

#### 2.2.2 UM-002: 用户登录

**需求描述**: 系统应验证用户凭证并返回认证 token

**功能详细说明**:

| 属性项 | 详细说明 |
|--------|----------|
| **标识符** | UM-002 |
| **名称** | 用户登录 |
| **优先级** | P0 - 最高优先级 |
| **业务价值** | 用户访问系统的入口，安全性的第一道防线 |
| **使用频率** | 每次会话开始时 |

**输入数据**:

| 字段名 | 类型 | 必填 | 约束 | 说明 |
|--------|------|------|------|------|
| accountID | String(25) | ✓ | - | 用户账号 ID |
| password | String | ✓ | - | 登录密码 |

**处理逻辑**:

```
1. 查询用户
   ├─ 根据 accountID 查询 users 表
   └─ 如不存在，返回错误"账户或密码不正确"

2. 验证密码
   ├─ 使用 bcrypt.verify(password, hashed_password)
   └─ 如不匹配，返回错误"账户或密码不正确"

3. 生成认证 token
   ├─ 当前：生成 mock token (f"mock_jwt_token_for_{accountID}")
   └─ 未来：生成真实 JWT token，有效期 24 小时

4. 返回成功响应
```

**输出数据**:

**成功响应** (HTTP 200):
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "accountID": "user123",
    "nickName": "张三",
    "token": "mock_jwt_token_for_user123"
  }
}
```

**失败响应**:
- 账户或密码错误 (HTTP 401): `{"code": 401, "message": "账户或密码不正确"}`

**安全考虑**:
- 不区分"账户不存在"和"密码错误"，统一返回"账户或密码不正确"(防止枚举攻击)
- 未来需实现：登录失败次数限制、IP 黑名单、验证码机制

**验收标准**:
- [ ] 正确凭证可以成功登录
- [ ] 错误凭证被拒绝
- [ ] 返回有效的 token
- [ ] 响应时间 < 200ms

**接口定义**:
- **端点**: `POST /api/users/login`
- **Content-Type**: `application/json`
- **认证**: 不需要

### 2.3 面试题目管理模块 (QM)

#### 2.3.1 QM-001: 题库分类管理

**需求描述**: 系统应维护三个领域的面试题库

**题库结构**:

| 表名 | 领域 | 题目数量 (目标) |
|------|------|----------------|

```python
{
  "ID": 1,              # Integer, 主键
  "degree": "中等",      # Enum: 简单/中等/困难
  "question": "请介绍一下你的项目经验",  # String(255)
  "answer": "参考答案..."  # String(255)
}
```

**管理功能**(后台):
- 题目增删改查
- 批量导入导出
- 难度标注
- 答案审核

#### 2.3.2 QM-002: 智能组卷

**需求描述**: 系统应根据用户选择的岗位自动生成面试题目序列

**输入**: 
- domain (领域，如"互联网")
- vocation (岗位，如"Java 开发")

**处理逻辑**:
```
1. 查询 vocation_signs 表
   └─ 获取该岗位的评价指标 (sign1-6)

2. 从对应题库抽题
   ├─ 第 1 题：简单难度 (破冰题)
   ├─ 第 2-3 题：中等难度 (专业能力)
   ├─ 第 4 题：困难难度 (压力测试)
   └─ 第 5 题：根据表现动态调整

3. 返回题目列表
```

**输出**: 
```json
[
  {"question": "自我介绍", "degree": "简单"},
  {"question": "技术细节 1", "degree": "中等"},
  {"question": "技术细节 2", "degree": "中等"},
  {"question": "挑战性问题", "degree": "困难"},
  {"question": "开放性问题", "degree": "中等"}
]
```

**约束**: 每次面试 3-5 道题

### 2.4 模拟面试与评测模块 (IM) ⭐核心模块

#### 2.4.1 IM-001: WebSocket 视频流接收

**需求描述**: 系统应通过 WebSocket 实时接收前端发送的视频流

**详细技术要求**:

| 属性项 | 详细说明 |
|--------|----------|
| **标识符** | IM-001 |
| **名称** | WebSocket 视频流接收 |
| **优先级** | P0 - 核心功能 |
| **协议** | WebSocket (RFC 6455) |
| **编码格式** | H.264 video + AAC audio |
| **封装格式** | WebM/MP4 |
| **分辨率** | 720P (1280×720) |
| **帧率** | 25-30 fps |
| **码率** | 1-2 Mbps |

**消息格式**:

#### 2.4.3 IM-003: 多模态分析触发

**需求描述**: 系统应并行触发 ASR 语音识别和视频分析

**并行处理架构**:

```

   ├─→ 提取音频 → ASR → 文本
   ├─→ 姿态识别 → BodyLanguage
   ├─→ 眼神检测 → EyeContact
   ├─→ 手部追踪 → HandMovement
   └─→ 情绪识别 → Emotion (7 类)

```

**分析维度**:

**1. 言语分析**:
- ASR 转录：语音 → 文本
- 流畅度：停顿次数、填充词 (嗯、啊) 统计
- 语速：字/分钟
- 语调：音高变化

**2. 肢体分析**:
- 姿态：坐姿端正度 (0-100 分)
- 眼神接触：注视摄像头时长占比
- 手部移动：适度手势 vs 过多小动作

**3. 情绪分析**:
- 7 种基本情绪：高兴、悲伤、愤怒、恐惧、惊讶、厌恶、中性
- 情绪稳定性：情绪波动方差
- 自信度：基于表情和姿态的综合评分

**输出数据结构**:

## 6. 安全性需求分析

### 6.1 认证与授权

#### 6.1.1 密码安全 (SEC-001)

**要求**:
- 使用 bcrypt 算法进行哈希加密
- salt rounds ≥ 10
- 禁止明文存储密码

**实现**:
```python
from passlib.context import CryptContext
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)
```

**验收**:
- [ ] 数据库中密码不可逆
- [ ] 相同密码哈希值不同 (随机 salt)
- [ ] 验证功能正常

---

#### 6.1.2 身份认证 (SEC-002)

**当前实现**: Mock JWT Token
```python
token = f"mock_jwt_token_for_{user.accountID}"
```

**未来规划**: 真实 JWT
```python
import jwt
from datetime import datetime, timedelta

def create_token(account_id: str) -> str:
    expire = datetime.utcnow() + timedelta(hours=24)
    payload = {
        "sub": account_id,
        "exp": expire,
        "iat": datetime.utcnow()
    }
    return jwt.encode(payload, SECRET_KEY, algorithm="HS256")
```

**Token 验证**:
- 所有需要认证的接口必须携带 Bearer Token
- 验证 token 有效性 (未过期、签名正确)
- 解析 token 获取 accountID

#### 6.1.3 权限控制 (SEC-003)

**原则**: 用户只能访问自己的数据

**实现**:

@app.get("/api/users/{account_id}/info")
async def get_user_info(account_id: str, token: str = Depends(oauth2_scheme)):

## 7. 可靠性与可用性需求

**目标**: 99.5% 可用性

**计算方式**:

**允许停机时间**:

#### 7.1.2 故障恢复 (REL-002)

**MTTR **(Mean Time To Recovery): < 2 小时

**MTBF **(Mean Time Between Failures): > 720 小时 (30 天)

**故障分级**:
| 级别 | 描述 | 响应时间 | 恢复时间 |
|------|------|----------|----------|
| P0 | 系统完全不可用 | 5 分钟 | 1 小时 |
| P1 | 核心功能受损 | 15 分钟 | 4 小时 |

#### 7.2.2 LLM 重试 (REL-004)

**重试策略**: 指数退避

```python
import time

def call_llm_with_retry(prompt, max_retries=3):
    for i in range(max_retries):
        try:
            return call_llm_api(prompt)
        except Exception as e:
            if i == max_retries - 1:
                raise
            wait_time = 2 ** i  # 1s, 2s, 4s
            time.sleep(wait_time)
```

#### 7.2.3 WebSocket 重连 (REL-005)

**重连策略**: 指数退避 + 抖动

```javascript
// 前端实现
let retryCount = 0;
const maxRetries = 5;

function reconnect() {
  if (retryCount >= maxRetries) {
    alert("连接失败，请刷新页面");
    return;
  }
  
  const delay = Math.pow(2, retryCount) * 1000 + Math.random() * 1000;
  setTimeout(() => {
    connectWebSocket();
    retryCount++;
  }, delay);
}
```

### 7.3 数据一致性

#### 7.3.1 事务保证 (REL-006)

**ACID 特性**:
- **原子性**: 事务要么全部成功，要么全部失败
- **一致性**: 事务前后数据一致
- **隔离性**: 并发事务互不干扰
- **持久性**: 事务提交后永久保存

**实现**:
```python
try:
    db.add(new_user)
    db.commit()  # 提交事务
except Exception as e:
    db.rollback()  # 回滚事务
    raise
```

try:
