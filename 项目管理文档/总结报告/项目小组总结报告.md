## 2.1 绪论

### 2.1.1 项目背景

在当今竞争日益激烈的就业市场中，面试是求职者获得理想工作的关键环节。然而，传统面试准备存在以下核心痛点：

- **专业指导资源稀缺、成本高**：高质量的面试辅导费用昂贵，学生与初入职场人群难以获得高频次模拟训练；
- **自主练习缺乏有效反馈**：求职者自行练习时，无法客观评估自身的肢体语言、面部表情、情绪状态与整体表现；
- **传统面试工具功能单一**：现有工具大多仅支持文字答题，缺少对非语言行为（肢体动作、眼神接触、微表情）的分析能力；
- **真人模拟效率低**：真人模拟面试需要协调双方时间，且反馈往往带有主观偏见，难以量化。

在此背景下，本团队决定开发一款基于**多模态 AI 技术**的智能化模拟面试平台——"面懵救星"（模拟面试智能体系统），通过计算机视觉、语音识别与大语言模型的深度融合，为用户提供沉浸式、高还原度、可量化评估的面试训练服务。

### 2.1.2 相关技术现状

本系统涉及的关键技术领域及行业现状如下：

| 技术领域           | 行业现状                                                             | 本系统采用方案                                       |
| -------------- | ---------------------------------------------------------------- | --------------------------------------------- |
| **大语言模型（LLM）** | 以 GPT-4、Claude、Qwen 为代表的 LLM 在自然语言生成和对话方面表现出色，已广泛应用于智能客服、教育辅导等场景 | 阿里云百炼 Qwen3.5-plus（通用对话）+ 讯飞星火（面试提问与评语生成）     |
| **计算机视觉**      | MediaPipe、OpenCV、YOLOv8 等开源框架已成熟，可在消费级硬件上实现实时姿态和面部关键点检测          | MediaPipe（姿态分析）+ DeepFace（情绪识别）+ YOLOv8（目标追踪） |
| **语音识别（ASR）**  | Whisper 等开源模型在多语种语音识别上达到商用水平                                     | 千问ASR语音转文本模型                                  |
| **实时通信**       | WebRTC 已成为浏览器端实时音视频通信的事实标准；WebSocket 协议广泛应用于需要全双工通信的 Web 应用      | WebRTC（前端视频采集）+ WebSocket（后端实时交互）             |
| **Web 开发框架**   | FastAPI 因其异步支持和高性能在 Python 后端生态中快速崛起；Vue 3 是当前主流前端框架之一           | FastAPI + Vue 3                               |

**本项目的核心创新点**在于将上述技术进行深度融合，构建了"LLM 智能对话 + 计算机视觉分析 + 多模态评测"一体化架构，实现从视频采集、AI 分析到报告生成的完整业务闭环。

### 2.1.3 项目的主要开发工作

本项目的主要开发工作涵盖以下五大方面：

1. **用户管理与权限系统**：实现用户注册、登录（JWT 鉴权）、个人信息管理、头像/简历上传、密码安全（BCrypt 加密）、角色权限控制等基础功能，为用户使用系统提供安全、便捷的入口。
2. **在线题库与学习资源系统**：构建多级分类题库（领域→岗位→难度），支持 17 个技术领域、50+ 细分岗位、三级难度（简单/中等/困难）的题目筛选与浏览；整合热门课程、视频资源、学习社区链接，为用户提供系统化的面试备考资源。
3. **模拟面试核心引擎**：这是系统的关键模块，涉及 WebRTC 视频采集、WebSocket 实时双向通信、ASR 语音转录、LLM 动态提问生成、视频切片存储（12 秒/段）与合并、静默检测自动推进面试流程等复杂技术实现。
4. **AI 多模态分析与评测报告系统**：集成 MediaPipe（姿态分析）、DeepFace（情绪识别）、YOLOv8（目标追踪）、Whisper（语音分析）等模型，实现 7 个维度的量化评分（身体姿态、眼神接触、面部情绪、手部动作、言语流畅度、语速、语调），并通过大模型生成结构化综合评语（优点总结 + 改进建议）；前端使用 Chart.js 实现雷达图、饼图、柱状图、横向柱状图等多种可视化图表。
5. **辅助功能模块**：包括 AI 助手（基于 Qwen3.5-plus 的多轮对话）、经验分享论坛（帖子发布/浏览/搜索/收藏）、历史报告管理（报告列表/详情/PDF 下载/视频回放）等扩展功能。

## 2.3 系统部署与测试工作情况

### 2.3.1 系统部署与调试

#### 部署环境配置

| 环境要素       | 配置说明                                                              |
| ---------- | ----------------------------------------------------------------- |
| 操作系统       | Windows 10/11、macOS 12+、Ubuntu 20.04+ 均支持                         |
| Python 版本  | 3.9+                                                              |
| Node.js 版本 | 16.0+                                                             |
| 数据库        | MySQL 8.0+，数据库名 interviewdata                                     |
| 应用服务器      | Uvicorn（开发）/ Gunicorn + Uvicorn Worker（生产）                        |
| 前端服务器      | Vue CLI dev server（开发）/ Nginx 静态文件服务（生产）                          |
| AI 框架依赖    | MediaPipe 0.10.14、DeepFace 0.0.91、TensorFlow 2.19.0、PyTorch 2.5.1 |

#### 部署步骤

1. **环境准备**：安装 Python 3.9+、Node.js 16+、MySQL 8.0+、FFmpeg
2. **后端部署**：
   - 创建 Python 虚拟环境并安装依赖（`pip install -r requirements.txt`）
   - 配置数据库连接字符串（database.py）
   - 配置 LLM API Key（ai\_service.py）
   - 启动 Uvicorn 服务：`python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`
3. **前端部署**：
   - 安装依赖：`npm install`
   - 启动开发服务器：`npm run serve`（开发模式，端口 8080）
   - 构建生产包：`npm run build`（生成 dist/ 目录，部署至 Nginx）
4. **数据库初始化**：FastAPI 启动时自动通过 `Base.metadata.create_all` 创建所有表结构

#### 关键调试工作记录

| 调试项          | 问题描述                              | 解决方案                                                       |
| ------------ | --------------------------------- | ---------------------------------------------------------- |
| 前后端跨域        | 前端 8080 端口请求后端 8000 端口时出现 CORS 错误 | 在 main.py 中配置 CORS 中间件，允许 localhost:8080 源                 |
| 视频格式兼容       | 前端 WebM 格式与后端处理不一致                | 统一 WebRTC MediaRecorder 的 MIME 类型为 `video/webm;codecs=vp8` |
| AI 依赖冲突      | MediaPipe 与 TensorFlow 版本不兼容      | 锁定依赖版本：mediapipe==0.10.14, tensorflow==2.19.0              |
| WebSocket 超时 | 回答结束后等待时间过长                       | 将静默超时设为 12s，倒计时 3s 提示优化用户体验                                |
| 报告 PDF 乱码    | 中文字体在 PDF 中不显示                    | 前端使用 html2pdf.js + html2canvas 方案，确保页面渲染完整后再导出             |

## 2.5 项目讨论与体会

### 2.5.1 对项目过程的体会

#### 项目团队的整体收获

1. **全流程软件工程实践**：这是团队大多数成员首次完整经历从项目立项、需求分析、系统设计、编码实现、测试联调到交付部署的软件工程全生命周期。通过 12 周的实践，每个人都对软件工程各阶段的意义和产出物有了真实的体感认知，不再只是课本上的理论知识。
2. **前后端分离架构的实战理解**：通过本项目，团队深刻体会到前后端分离架构的优越性——前端和后端可以独立开发、独立调试、独立部署。接口文档（Apifox）在其中起到了"契约"的关键作用：前后端严格基于预先定义的接口规范开发，使得 W11 的全链路联调能够高效完成。
3. **AI 工程化的挑战与经验**：项目中集成计算机视觉和 LLM 的过程让团队认识到，"AI 落地"的难点不在于模型本身（MediaPipe、DeepFace 等开源模型已相当成熟），而在于如何将其"工程化"——包括输入输出的格式适配、不同模块间的数据协同、异步调用的超时处理、性能瓶颈的发现与优化等。
4. **团队协作的价值**：6 人团队按职责清晰分工（PM、前端 2 人、后端 3 人），每周站会同步进度、暴露问题，代码审查保障质量，文档共享消除信息差。良好的协作机制是项目按时完工的关键保障。
5. **文档对项目质量的保障作用**：项目前期在需求分析和系统设计上投入了 W1-W7 共 7 周时间（占总周期的 58%），产出了 SRS、SDD、详细设计、接口文档等一系列规范性文档。虽然前期投入较大，但清晰的需求基线和设计蓝图在开发阶段大大减少了因理解不一致导致的返工，验证了"磨刀不误砍柴工"的软件工程理念。

| 3  | **文档驱动，沟通高效**  | SRS → SDD → 详细设计 → 接口文档 的文档体系使 6 人团队始终保持对齐，减少了口头沟通的偏差                                |
| 4  | **风险预判，应对及时**  | 项目计划书中预先识别了技术风险、安全风险、进度风险、资源风险 4 类 12 项风险并制定了应对措施，实际执行中 W11 发现的安全漏洞和性能问题均在预设的应对框架内解决 |

#### 不足与改进方向

| 编号 | 不足                | 改进建议                                                                                         |
| -- | ----------------- | -------------------------------------------------------------------------------------------- |
| 1  | **设计阶段耗时偏长**      | W1-W7（设计阶段）占全周期 58%，虽然保障了设计质量，但压缩了开发后期的功能迭代空间。建议未来在保证设计质量的前提下，通过模板化文档和应用 AI 辅助写作来缩短设计周期      |
| 2  | **自动化测试覆盖不足**     | 当前主要依赖手动联调测试，缺少单元测试和集成测试的自动化覆盖（如 pytest 单元测试、Playwright E2E 测试），回归测试效率较低。建议在后续迭代中补充分层自动化测试体系 |
| 3  | **代码审查频率不均衡**     | 代码审查机制虽然在计划中明确，但执行过程中 W5-W8 开发高峰期审查频率有所下降，导致部分代码风格不一致。建议建立每日/隔日固定审查窗口                        |
| 4  | **前端状态管理复杂度控制不足** | 部分 Vue 组件中状态管理逻辑较为分散（如面试页面 Billing.vue 的 data 属性过长），建议进一步利用 Pinia 进行模块化状态管理重构                |
| 5  | **高并发场景验证不充分**    | 当前仅进行了单用户场景的完整联调，多用户并发场景下的性能压测（如同时 5 人面试时的 WebSocket 并发和 AI 推理负载）未充分进行。建议在后续迭代中补充压力测试        |
| 6  | **知识沉淀与交接文档不足**   | AI 分析引擎的模型配置和环境依赖较为复杂，目前缺少详细的环境配置手册和开发者上手文档，不利于项目交接和维护。建议补充开发者 Wiki 和运维手册                    |
| 7  | **论坛功能的社区化程度有限**  | 当前论坛数据存储在 localStorage 中，无法在用户间共享，社区化程度不足。建议后续接入后端数据库，实现真正的多用户社区功能                           |
